What's inside

Engineered like a real internal tool.

Every screen follows one pattern: a dense data table is the surface, a right-side drawer is the detail. No modal stacks, no decorative KPI walls.

Table-first surfaces

Dense op-dtable grids with sticky headers, aging-grouped rows, bulk-select and a dark batch-action bar. Built for operators who scan.

Drawer detail pattern

Records open in a slide-in right drawer — context stays, the table never unmounts. Tabs, key-value grids and inline mini-tables included.

RBAC, built in

A capability matrix gates routes and data. Three roles, scoped providers — every module mounts already filtered to the signed-in user.

Domain-driven architecture

A pure domain/ layer holds business rules and types — zero imports from React, services or UI. Logic is testable in isolation.

Command palette

A global ⌘K search across every entity the user can see — keyboard-first navigation, RBAC-scoped results.

Swappable data layer

One DataService interface, two adapters: a latency-simulating mock and a real backend. Switch with an env flag — views never change.

Nine modules

A full operations workspace, not a starter.

Every module is wired to the data layer with real flows — create, edit, advance, resolve. Replace the sample domain and the structure holds.

Architecture

Layered, typed, and honest about boundaries.

The composition root wires providers in dependency order. The data layer only ever mounts behind an authenticated user — so modules never defend against a null session.

01 One column does the work

Each screen has a primary surface; everything else is sparse support.

02 Hairlines, not shadows

Depth from 1px borders and surface tints — no glow, no gradients in the tool.

03 Status as label

A small colored dot and one word. Pills only where density demands it.

04 Tabular numerals always

Every figure aligns. IBM Plex Mono for IDs, timestamps and money.

            <BrowserRouter>
              <App />
            </BrowserRouter>
          </DataServiceProvider>
        </AuthGate>
      </AuthProvider>
    </ErrorBoundary>
  );
}
